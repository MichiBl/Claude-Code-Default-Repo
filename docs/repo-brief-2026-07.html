Was es macht

Browser-basiertes Lernspiel, das die korrekte Dosierung von Kreon-Kapseln (Pankreas-Enzymersatz) für Lebensmittel und Mahlzeiten trainiert — eine Routineaufgabe, die CF-Patient:innen mehrfach täglich vor jeder Mahlzeit selbst einschätzen müssen.

Bewusst minimal: kein TypeScript, kein State-Framework, kein Backend. npm run build erzeugt eine einzelne dist/index.html — Spiel, Schrift und Design komplett eingebettet, läuft per Doppelklick offline auf jedem Rechner.

Neu seit Mai

Single-File-Build als Weitergabeformat

Der Build bettet alles in eine HTML-Datei ein — verteilbar per E-Mail, USB-Stick oder Download, ohne Installation und ohne Internet. Genau das Format, das für die geplante Weitergabe über den Mukoviszidose e.V. gebraucht wird; die Projektvorstellungs-PDF liegt bereits im Repo.

Layout skaliert automatisch (useFitScale)

Neuer Hook berechnet aus der Fenstergröße einen Zoom-Faktor — das Spiel passt jetzt auf 13″-Laptops ebenso wie auf große Monitore und Handys. Verifiziert mit Playwright über fünf Viewports, gegen Dev-Server und Single-File-Build.

ARCHITEKTUR.md mit Mermaid-Diagrammen

Bausteine, Datenfluss und Screen-Ablauf sind jetzt dokumentiert — die Lücke zwischen „Single-File-Spielzeug" und „Projekt, das jemand anderes weiterpflegen könnte" schließt sich.

Bewertung
  • Stärke: Scope und Implementation passen weiter perfekt zusammen — kein Over-Engineering.
  • Stärke: Das Auslieferungsformat (eine Datei, offline) ist exakt auf die Zielgruppe zugeschnitten.
  • Schwäche: Weiterhin keine Tests und keine CI — für den aktuellen Scope okay, wird aber zur Hypothek, sobald der Verein Änderungswünsche liefert. Im Klartext: Jede Änderung muss von Hand durchgespielt werden, es gibt kein Sicherheitsnetz gegen Regressionen.
  • Schwäche: 808-Zeilen-Hauptdatei mit Inline-Styles — Refactoring-Schuld bei Wachstum.

Was es macht

Multi-Agent-System, das täglich ein Morning Briefing zu einer persönlichen Aktien-Watchlist generiert und per E-Mail versendet. Die Pipeline aus dem Mai-Plan ist jetzt real:

  • Watchlist Reader — liest watchlist.json (Ticker, Name, ISIN).
  • News Crawler — sucht via Gemini Grounded Search News der letzten 24 h, filtert und sanitisiert am Ingress.
  • Digest Writer — fasst zusammen, klassifiziert Sentiment, rendert Markdown + HTML, versendet via Gmail-SMTP.

Orchestrierung als SequentialAgent über Google ADK; State-Sharing über die ADK-Session. Läuft lokal via uv oder als Docker-Container (Multi-Stage, non-root, Secrets nur zur Laufzeit).

Neu seit Mai

Phase 1 komplett: die Pipeline funktioniert

Alle 18 Kriterien der Kern-Pipeline erfüllt, dazu 4/5 E-Mail-Versand und 7/8 Polish & Tests. Das Spec-First-Experiment aus dem Mai-Brief hat seine zentrale Frage beantwortet: Ja, der Ansatz hält — die Stubs mit vorformulierten Prompts wurden planmäßig zur Implementierung.

Trust-Boundary-Härtung (PR #27)

Web-Inhalte und LLM-Output werden als nicht vertrauenswürdig behandelt: unsichtbare Bidi-/Zero-Width-Zeichen werden am Ingress gestrippt (Display-Spoofing), jeder Link zeigt die echte Ziel-Domain (Phishing-Mitigation), Grounding-URLs werden per Domain-Abgleich zugeordnet. Im Klartext: Eine manipulierte News-Quelle kann in der Morgen-Mail keine Links mehr verstecken, die woandershin führen, als sie behaupten.

Supply-Chain-Disziplin

uv.lock als Quelle der Wahrheit mit CI-Check, SHA-gepinnte GitHub Actions, Secret-Scanning auf drei Ebenen (pre-commit, Claude-Hook, CI-Backstop) mit gemeinsamer Baseline.

Was noch fehlt
  • 2.4 — Manueller Versand-Test: Rendering in Gmail Web + Mobile verifizieren.
  • 3.1 — Sentiment-Stichprobe: ≥ 80 % Plausibilität über echte Gemini-Läufe belegen.
  • 4.2 / 4.3 — Cloud-Run-Deploy + Cloud Scheduler: erst danach läuft das Briefing wirklich jeden Morgen ohne manuellen Anstoß.

Was es macht

Lokaler, datensparsamer Assistent für Mail und Kalender als PoC auf einem M1-Mac mit 8 GB. Apple Mail und Apple Kalender liefern lokal gecachte Daten über AppleScript-Bridges an ein Python-CLI, das ein lokales LLM (Ollama) aufruft — ausschließlich read-only.

11 Kommandos: Posteingang triagieren (wichtig/FYI/Werbung), zusammenfassen mit Action Items, Antwort-Entwürfe, Termine aus Mails erkennen, Tagesbriefing, Konflikte und Kategorien im Kalender (bewusst deterministisch, ohne LLM), Meeting-Vorbereitung aus zugehörigen Mails, Übersetzen, Umformulieren, Notizen ordnen.

Stack
Python 3.11 Ollama Gemma 4 E2B (4-bit) AppleScript / osascript requests + dotenv ruff + mypy pytest (417) gitleaks launchd (vorbereitet)

Architektur-Kniff („Weg B"): Apple Mail als Auth-Layer — die komplette OAuth-Komplexität von Gmail/live.com/web.de erledigt der Mail-Client, das Skript liest nur den lokalen Cache. Kein Token-Handling, keine Cloud-API.

Technische Highlights

Harte Invarianten statt guter Vorsätze

READ-ONLY (kein Schreibpfad im Code), kein Cloud-LLM im Laufzeitpfad (Loopback-Check lehnt fremde Hosts beim Start ab), keine PII ins Repo, Outputs mit 0600/0700-Rechten ins Repo-Verzeichnis confined. Die Grenzen stehen in CLAUDE.md und werden von Review-Agent, Verify-Hook und CI geprüft. Im Klartext: Das Werkzeug kann konstruktionsbedingt keine Mail versenden und keine Daten in die Cloud schicken — auch nicht aus Versehen.

Prompt-Injection-Mitigation über die ganze Kette

AppleScript-Bridges strippen die internen Record-Trennzeichen (kein Einschleusen gefälschter Mail-Records), Python filtert Steuerzeichen/ANSI-Escapes aus Fremdinhalten und Modell-Output, Prompts markieren Mail-Inhalte explizit als Daten, nicht als Anweisungen. Nach dem Security-Review zusätzlich: allow_redirects=False im Ollama-Client, damit ein gekaperter localhost-Port keine Prompts nach außen umleiten kann.

Hardware-Disziplin als Architektur-Vorgabe

M1 mit 8 GB ist die harte Grenze: Gemma 4 E2B in 4-bit, num_ctx 8192, Tasks klein und klar abgegrenzt. Kalender-Konflikte und Kategorisierung laufen bewusst deterministisch ohne LLM — das Modell wird nur eingesetzt, wo es wirklich gebraucht wird.

Bewertung
  • Stärke: Erster Volltest des Default-Repo-Workflows — von null auf 417 Tests, mypy, CI und Security-Review in neun Tagen.
  • Stärke: Test-zu-Code-Verhältnis ~4:1; die Sicherheits-Invarianten sind selbst durch Tests abgedeckt (test_security.py).
  • Schwäche: AppleScript-Bridges sind fragil gegenüber macOS-/Mail-Updates — bekanntes PoC-Risiko.
  • Bewusste Grenze: Nur privates Setup; für den Übertrag in den Arbeitskontext dokumentiert docs/datenschutz.md die zusätzlichen Pflichten.

Was es ist

Wiederverwendbares Standard-Setup für neue Projekte — explizit destilliert aus Stock-Wise, News Agent und local-mail-ai. setup.sh /pfad/zum/projekt kopiert das komplette Gerüst, ohne existierende Dateien zu überschreiben; danach füllt Claude Code die CLAUDE.md-Platzhalter anhand des Zielprojekts aus.

Der --diff-Modus zeigt pro Template-Datei fehlt / identisch / weicht ab — Verbesserungen am Template lassen sich so gezielt in ältere Projekte zurückspielen. Das Template ist damit kein Einmal-Kopierer, sondern ein Synchronisations-Werkzeug.

Was drin ist
  • CLAUDE.md-Template — Projektbeschreibung, Tech-Stack, harte Grenzen, Konventionen, Build-Gates als auszufüllende Struktur.
  • 4 Subagents — requirements-engineer, solution-architect, code-reviewer, qa-engineer; dazu der /feature-Skill, der die Pipeline orchestriert.
  • Hooks — secret-scan.sh (blockt commit/push mit Secrets), verify.sh (Stop-Hook führt die Projekt-Gates aus), session-start.sh.
  • 4-Schichten-Secret-Schutz — Claude-Hook, gitleaks pre-commit, CI-Workflow als Backstop, GitHub Push Protection.
  • CI-Vorlagen — ci-node.yml.example und ci-python.yml.example, dazu dependabot.yml und .gitleaks.toml.
Bewertung
  • Stärke: Der Beweis liegt vor — local-mail-ai ist das erste Projekt, das komplett auf diesem Gerüst entstand, und war in neun Tagen auf Production-PoC-Niveau.
  • Stärke: Der --diff-Rückkanal macht das Template zur lebenden Infrastruktur statt zur veraltenden Kopiervorlage.
  • Hinweis: Auch dieses Repo durchlief den eigenen Prozess — 7 gemergte PRs inklusive Review- und Security-Runde. Das Template hält sich an seine eigenen Regeln.
04 — Was ich daraus mitnehme

Vier Beobachtungen.

Was sich in zwei Monaten AI-assistierter Entwicklung verändert hat — gemessen an den eigenen Vorhersagen aus dem Mai-Brief.

01

Spec-First hat den Belastungstest bestanden

Die offene Frage aus dem Mai — „hält Spec-First, was es verspricht?" — ist beantwortet: Der News Agent ging von 17 % auf 90 %, exakt entlang des Phasenplans, mit 459 Tests. Und local-mail-ai zeigt den Ansatz von Tag eins: CLAUDE.md mit harten Grenzen zuerst, dann Code — neun Tage bis zum getesteten PoC.

02

Der Workflow ist jetzt ein Produkt

Die Meta-Reflexion aus dem Mai-Brief („beim nächsten Projekt starte ich mit CLAUDE.md, Phasenplan und Review-Subagent") ist nicht Vorsatz geblieben, sondern das Default-Repo geworden: destilliert aus drei Projekten, mit setup.sh --diff als Rückkanal für Verbesserungen. Neue Projekte starten nicht mehr bei null, sondern beim erprobten Gerüst.

03

Security ist vom Feature zum Querschnitt geworden

Am 5. Juli liefen Security-Reviews über alle vier aktiven Repos — Ergebnis: keine kritischen Findings, nur Defense-in-Depth-Härtungen (DB-Grants, Bidi-Stripping, Redirect-Blocking). Das ist der eigentliche Reifegrad-Sprung: Sicherheit wird nicht mehr nachgerüstet, sondern die Invarianten stehen in CLAUDE.md und werden von Hooks und CI erzwungen.

04

Testcode übersteigt Produktivcode — und das ist der Punkt

News Agent ~3:1, local-mail-ai ~4:1 Test- zu Produktivcode; Stock-Wise von 242 auf 728 Tests. AI senkt die Kosten des Testschreibens so weit, dass die Frage nicht mehr „ob" lautet, sondern welche Tests Wert haben — Invarianten, Trust-Boundaries, Regressionen. Kreon-Koch bleibt der bewusste Gegenpol: null Tests, weil der Scope es (noch) trägt.
